# 自用远程桌面方案（基于 RustDesk 改造）

> 版本：v0.1（待 Codex 评审）　日期：2026-10-19
> 标注说明：**[已核实]** 表示已对照 RustDesk 源码确认；**[待验证]** 表示需要在实施阶段实测确认。

## 1. 需求（已与用户确认）

| 项目 | 结论 |
|---|---|
| 设备 | Mac（Apple Silicon M 系列）、Windows 11 |
| 网络 | 两台电脑经常不在同一网络（如家里和公司），都没有固定 IP 和域名 |
| 连接方式 | 租一台云服务器做"牵线 + 兜底中转" |
| 控制方向 | 双向；**优先 Mac 控 Windows**（Windows 是主要被控端） |
| 功能 | 画面 + 键盘鼠标（核心）、**剪贴板同步**、**无人值守**（开机自启、锁屏/登录界面可控） |
| 不需要 | 文件传输、远程声音、多显示器切换（可在客户端里关闭或隐藏） |
| 流畅度 | 日常办公流畅（写代码、看文档），不追求视频/游戏级 |
| 使用范围 | 仅自用，不分发 |
| 定制要求 | 端口、进程名、程序名可自定义 |

## 2. 总体架构

```
            ┌────────────── 云服务器（有公网 IP）──────────────┐
            │  hbbs：ID 注册 / 打洞协调（rendezvous）            │
            │  hbbr：中继（打洞失败时转发画面数据）              │
            └──────────────▲───────────────────▲──────────────┘
                 注册/心跳 │                   │ 注册/心跳
          ┌────────────────┴──┐   P2P 直连   ┌──┴────────────────┐
          │ Mac（控制端+被控端）│◀═══════════▶│ Windows（被控端为主）│
          └───────────────────┘ 失败则经 hbbr └───────────────────┘
```

连接流程：

1. 两台电脑开机后，客户端主动连接云服务器的 hbbs 注册自己的 ID（出站连接，所以不需要固定 IP）。
2. Mac 发起连接时，hbbs 交换双方的公网地址，双方尝试 UDP/TCP 打洞直连。
3. 打洞成功：画面、键鼠、剪贴板数据直接点对点传输，不占用云服务器带宽。
4. 打洞失败（对称 NAT、公司防火墙等）：自动改走 hbbr 中继。
5. 全程端到端加密：客户端内置服务器公钥，只有持有该公钥的客户端能接入你的服务器。

为什么不让 Windows 直接当服务器：Windows 没有公网 IPv4，从外网无法主动连进去。若家宽有公网 IPv6 也可以直连，但公司网络常常没有 IPv6，作为兜底不可靠。所以云服务器只承担"牵线 + 兜底"，这样最稳。

## 3. 组件与改造范围

### 3.1 服务端（rustdesk-server，开源版即可）

- 部署：Docker Compose 运行 `hbbs` 和 `hbbr` 两个容器（或直接运行二进制，配合 systemd）。
- **自定义端口 [已核实]**：
  - `hbbs -p <P>`：监听 `P`（TCP+UDP，注册/打洞）、`P-1`（TCP，NAT 类型检测）、`P+2`（TCP，WebSocket，网页版才用，可不开放）。默认 P=21116。
  - `hbbr -p <R>`：监听 `R`（TCP，中继），`R+2` 是 WebSocket。默认 R=21117。
  - 例如选 P=31116、R=31117，防火墙放行 TCP 31115–31117、UDP 31116。
- **只允许自己的客户端接入 [已核实]**：`hbbs -k _` / `hbbr -k _` 强制要求客户端持有服务器公钥（`id_ed25519.pub`，首次启动自动生成），别人即使知道地址也用不了。
- 服务器规格：1 核 1G 足够；带宽见第 5 节。

### 3.2 客户端（rustdesk，自己从源码编译）

需要改的地方（RustDesk 的配置常量在子模块 `libs/hbb_common/src/config.rs` 中）**[已核实]**：

| 改什么 | 位置 | 说明 |
|---|---|---|
| 内置服务器地址 | `RENDEZVOUS_SERVERS` | 改成云服务器的 IP 或域名 |
| 内置服务器公钥 | `RS_PUB_KEY` | 改成 `id_ed25519.pub` 的内容 |
| 默认端口 | `RENDEZVOUS_PORT` / `RELAY_PORT` | 改成 31116 / 31117（与服务端一致） |
| 程序名 | `APP_NAME` | 影响窗口标题、配置目录、服务名 |
| 组织名 | `ORG` | 影响 macOS Bundle ID 前缀与配置路径 |
| 进程名/可执行文件名 | Cargo 包名、Windows 安装脚本、macOS `Info.plist` 和 Flutter 工程配置 | **[待验证]** 具体文件清单要在实施时梳理，涉及的地方较多 |
| 图标 | `res/` 下的图标资源 | 可选 |
| 隐藏不需要的功能 | 默认关闭文件传输、音频；UI 上隐藏入口 | 可选，第一版先用"设置里关闭"代替改 UI |

不改源码也能用的替代做法（作为第 0 阶段验证）：直接用官方客户端，在"网络设置"里填自己的服务器地址、端口和公钥。先用这种方式验证整条链路，再投入编译定制版。

### 3.3 无人值守

**Windows 11（主要被控端）**

- 以"安装版"安装，客户端注册为 Windows 服务（以 SYSTEM 身份运行），开机自启，能控制 UAC 弹窗和登录界面。
- 设置固定密码（强密码），关闭"需要对方确认"。
- 电源设置：关闭自动睡眠；可选开启网络唤醒（需路由器配合，第一版不做）。

**macOS（M 系列，次要被控端）**

- 需要授予三项系统权限：屏幕录制、辅助功能、输入监控。
- 客户端安装后通过 LaunchAgent / LaunchDaemon 开机自启。
- 锁屏/登录界面控制：**[待验证]** macOS 对登录窗口的支持比 Windows 弱，需要实测在当前 macOS 版本下是否可用。如果不行，第一版接受"Mac 需要已登录"的限制。
- **签名问题（重要）**：macOS 的权限授权和应用签名绑定。每次重新编译如果签名变了，三项权限需要重新授予。对策：用固定的自签名证书（或 Apple 开发者证书）签名，保证每次编译的签名一致。

### 3.4 剪贴板同步

RustDesk 自带文本剪贴板同步（双向），保持开启即可。

### 3.5 Mac 控 Windows 的键盘习惯

Mac 的 Command 键在 Windows 上对应 Win 键，而用户习惯 Command+C/V 复制粘贴。
**[待验证]** RustDesk 是否有现成的"Command ↔ Ctrl 互换"选项；如果没有，在客户端加一个按键映射开关（改动量小）。

## 4. 安全设计

1. 服务端开启 `-k _`，只接受内置公钥的客户端。
2. 连接全程加密（RustDesk 基于 NaCl 的端到端加密），中继服务器看不到明文画面。
3. 被控端使用强固定密码；可选开启 RustDesk 的双重认证（TOTP）**[待验证：开源版是否支持]**。
4. 云服务器防火墙只放行上述端口，SSH 只允许密钥登录。
5. 使用非默认端口，降低被扫描的概率。
6. 私钥 `id_ed25519` 只保存在服务器上，并单独备份。

## 5. 带宽与云服务器选型

- **打洞成功时**数据不经过服务器，服务器只有很小的心跳流量。
- **中继时**办公场景 1080p（VP9/H.264）大约 1–3 Mbps，画面大面积变化时峰值约 5 Mbps。
- 建议：峰值带宽 ≥ 5 Mbps，或选按流量计费、峰值带宽更高的轻量服务器套餐。
- 机房地域：选离两台电脑都近的地域，延迟更低。
- 画质：设置里选"均衡"或"优化速度"，并限制最大分辨率，进一步降低带宽。

## 6. 编译与发布

- 推荐方式：fork RustDesk 仓库到自己的 GitHub 账号，修改上述常量后，用仓库自带的 GitHub Actions 工作流编译 Windows x64 和 macOS arm64 安装包，避免在本机搭建 Rust + Flutter + vcpkg 的复杂环境。**[待验证]** 工作流里有些步骤依赖官方的签名密钥，fork 后需要裁剪或替换。
- macOS：用固定证书签名（见 3.3）；未公证的应用首次打开需要右键"打开"。
- 版本管理：保留官方 upstream 作为远程仓库，自己的修改集中在少数文件里，方便以后合并官方更新。

## 7. 实施步骤

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| 0. 链路验证 | 买云服务器，Docker 部署 hbbs/hbbr（自定义端口 + `-k _`）；两台电脑装官方客户端并填入自己的服务器 | Mac 能远程控制 Windows，双向都通；记录是直连还是中继 |
| 1. 定制编译 | fork 仓库，改服务器地址、公钥、端口、程序名、进程名，Actions 出包 | 定制版无需手动配置即可连上自己的服务器 |
| 2. 无人值守 | Windows 装服务版、设固定密码；Mac 授权、固定签名、开机自启 | 两台电脑重启后无人操作也能被远程连接 |
| 3. 体验调优 | Command/Ctrl 映射、画质参数、关闭不需要的功能 | Mac 控 Windows 日常办公无明显卡顿 |
| 4. 加固 | 防火墙、SSH、私钥备份、可选 TOTP | 第 4 节各项完成 |

## 8. 测试清单

- 家里网络 ↔ 公司网络、手机热点 ↔ 家里网络，分别测试连接成功率、直连或中继、延迟。
- Windows：锁屏、登录界面、UAC 弹窗、重启后自动上线。
- Mac：重启后自动上线；锁屏状态下的表现。
- 剪贴板：中文、长文本双向复制。
- 中继模式下的流量统计，验证第 5 节的带宽估算。
- 断网重连：网络切换后能否自动恢复注册。

## 9. 风险与备选

| 风险 | 影响 | 对策 |
|---|---|---|
| macOS 登录界面无法控制 | Mac 未登录时无法远程 | 接受限制（Mac 是次要被控端），或设置自动登录 |
| 编译环境复杂、Actions 依赖官方密钥 | 定制版出包受阻 | 先用官方客户端 + 自建服务器（阶段 0 的状态已可日常使用） |
| 重新编译后 Mac 权限失效 | 每次升级要重新授权 | 固定签名证书 |
| 跟进官方更新的合并成本 | 长期维护负担 | 改动集中在少数文件；只在需要时合并 |
| 云服务器到期或被封端口 | 无法连接 | 续费提醒；端口可随时修改 |
| AGPL-3.0 许可证 | 自用无影响，分发需开源 | 仅自用 |

备选方案（未采用）：Tailscale / ZeroTier 组网后直连，省掉云服务器但依赖第三方，国内中继节点延迟不稳定；从头自研，工作量大，打洞、编码、无人值守都要重写。
