## 1. 需求（已与用户确认）

| 项目 | 结论 |
|---|---|
| 设备 | Mac（Apple Silicon M 系列）、Windows 11 |

| 流畅度 | 日常办公流畅 |
| 使用范围 | 仅自用，不分发 |
| 定制要求 | 端口、进程名、程序名可自定义 |

## 2. 总体架构

```
            ┌────────────── 云服务器（固定公网 IP）─────────────┐
            │  hbbs：ID 注册 / 打洞协调（rendezvous）            │
            │  hbbr：中继（打洞失败时转发加密数据）              │
            └──────────────▲───────────────────▲──────────────┘
                 注册/心跳 │                   │ 注册/心跳
          ┌────────────────┴──┐   P2P 直连   ┌──┴────────────────┐
          │ Mac（控制端+被控端）│◀═══════════▶│ Windows（被控端为主）│
          └───────────────────┘ 失败则经 hbbr └───────────────────┘
```

连接流程：

1. 两台电脑开机后，客户端主动连接 hbbs 注册 ID（出站连接，所以终端不需要固定 IP）。
2. 发起连接时，hbbs 交换双方地址，双方尝试打洞直连。
3. 打洞成功则点对点传输；失败（对称 NAT、公司防火墙等）则走 hbbr 中继。
4. 客户端用内置的服务器公钥校验服务器身份，并与被控端完成安全握手，中继只转发密文。
5. **谁能控制被控端，由被控端的永久强密码 + TOTP 决定**，不是由服务器公钥决定（评审 #1）。

服务器公钥的定位：它是"服务器信任根"，客户端靠它确认连的是自己的服务器。它可以从安装包里提取，因此**不能当作接入凭据**。`hbbs/hbbr -k _` 仍然保留，作用是拒绝不带匹配 key 的客户端、减少噪声，但不负责设备认证 **[已核实：rendezvous_server.rs 中 `RegisterPeer` 分支不校验 key]**。

如果以后要求服务器只对自己的两台设备开放，再加一层按设备认证的 VPN（例如 WireGuard），把 hbbs/hbbr 端口只开放给 VPN 内网。第一版不做。

## 3. 组件与改造范围

### 3.1 服务端（rustdesk-server 开源版）

- 部署：Docker Compose 运行 hbbs 和 hbbr。**固定镜像版本或 digest**，不用 `latest`（评审 #5）。
- 两个容器挂载**同一个持久化数据目录**，共享 `id_ed25519` / `id_ed25519.pub`。
- hbbs 显式指定中继地址：`hbbs -p <P> -r <公网IP>:<R> -k _`；hbbr：`hbbr -p <R> -k _`。
- 端口规则 **[已核实]**：
  - hbbs 监听 `P`（TCP+UDP）、`P-1`（TCP，NAT 类型检测）、`P+2`（TCP，WebSocket）。默认 P=21116。
  - hbbr 监听 `R`（TCP）、`R+2`（TCP，WebSocket）。默认 R=21117。
  - 示例 P=31116、R=31117：防火墙放行 TCP 31115–31117、UDP 31116。**不用网页版就不开放 WebSocket 端口**（31118、31119）。
- 非默认端口只减少扫描噪声，不承担鉴权或加密职责。
- 规格：1 核 1G 足够；带宽见第 5 节。

### 3.2 客户端（自己从源码编译）

**命名原则（评审 #3）**：第一版用**一个统一的产品名 `homeuu`**同时驱动主程序文件名、安装目录、Windows 服务名、Mac 产品名和 Bundle ID。不改 Rust 库名、DLL/dylib 名和内部 FFI 符号，避免无谓改动。

需要处理的范围（逐文件、逐行的完整清单见[评审报告"第 3.2 节应补齐的改名文件清单"](方案-评审意见.md#第-32-节应补齐的改名文件清单)）：

| 范围 | 要点 |
|---|---|
| 服务器配置常量 | `hbb_common/src/config.rs`：`RENDEZVOUS_SERVERS`、`RS_PUB_KEY`、`RENDEZVOUS_PORT`、`RELAY_PORT` **[已核实]** |
| 运行时名称 | 同文件的 `APP_NAME`、`ORG`。Windows 服务名跟随 `APP_NAME` |
| Windows 主程序 | `flutter/windows/CMakeLists.txt` 的 `BINARY_NAME` 决定 exe 名；`Runner.rc` 的产品信息同步 |
| Windows 安装包 | MSI 打包脚本传入 `--app-name`；EXE 打包入口路径和产物名 |
| macOS 产品名和 Bundle ID | `AppInfo.xcconfig` 和 `project.pbxproj` 的 Debug/Profile/Release 三处全部统一；`Info.plist` 的 URL scheme；Scheme 和 Nib 中的模块名 |
| macOS launchd 与安装脚本 | `agent.plist`、`daemon.plist`、`install/uninstall/update.scpt` 中的 Label、Bundle ID、路径 |
| macOS 硬编码组织前缀 | `src/platform/macos.rs` 里有硬编码的 `com.carriez.*`，必须改成与 `ORG` 一致，否则安装检测、升级、卸载会找错服务 **[已核实]** |
| macOS helper 进程 | 如果 service 进程也要改名，同步 Cargo bin 名、build.py、签名脚本和 macos.rs 中的引用 |

**子模块注意（评审 #8）**：`hbb_common` 是 git 子模块。必须 fork `hbb_common`，在 fork 里提交修改，并把主仓库 `.gitmodules` 的 URL 和 gitlink 指向自己的提交，否则 Actions 会拉回上游原配置。

**旧配置覆盖**：客户端本地配置的服务器地址和公钥优先于内置默认值。从官方客户端换到定制版时，先清空旧配置再装，并在测试中验证"全新安装"和"覆盖升级"两种情况（评审 #5）。

### 3.3 无人值守

**Windows 11（主要被控端）**

- 安装版安装，服务以 LocalSystem 身份、自动启动 **[已核实：MSI 按此创建服务]**。
- 只使用永久密码（关闭临时密码），关闭"需要对方确认"。
- 电源设置关闭自动睡眠。
- 验收要分别覆盖：未登录、锁屏、UAC 安全桌面三种状态下的画面**和输入**。

**macOS（M 系列，次要被控端）**

三种状态分开定义（评审 #2）：

| 状态 | 预期 | 说明 |
|---|---|---|
| 已登录 + 锁屏 | 应可远程解锁并操作 | 需真机验收 |
| 注销后的登录窗口 | 应可远程看到并输入密码 | RustDesk 的 `agent.plist` 声明了 `LoginWindow` 会话 **[已核实]**，**[需真机验收]** |
| 重启后的 FileVault 解锁界面 | **RustDesk 无法控制** | 这是系统启动前的界面，RustDesk 进程还没运行 |

关于 FileVault，**用户已选 B**：关闭 FileVault 并开启自动登录。重启后系统自动登录到用户会话，homeuu 随登录启动，因此重启后可远程连接。代价是磁盘不加密，Mac 丢失时数据有风险；配合开机后自动锁屏（锁屏可远程解锁）降低他人直接接触 Mac 的风险。

（未采用：A 保留 FileVault、重启后本机解锁；C 另搭 SSH 解锁通道。）

系统权限：屏幕录制、辅助功能为核心权限；输入监控视系统版本而定。首次安装、授权、安装服务必须本人在本机完成。

**签名与权限保留（评审 #4）**：macOS 权限绑定的是"应用身份"（Bundle ID + 签名身份 + designated requirement），不是某次编译的字节。所以：

- 每次构建都用**同一个签名身份**和同一个 Bundle ID。
- **用户决定先走免费路线**：在自己的 Mac 上用 Xcode 登录普通 Apple ID，获得免费的 Apple Development 证书。它带 Team ID，可以避开纯自签名在 hardened runtime 下的动态库验证问题。**[需真机验收]**：免费证书能否正常签名、运行、保持权限，以及证书有效期到期后续签对权限的影响。
- 因为证书只在自己的 Mac 上，macOS 安装包改为**在本机签名**：Actions 只出未签名产物，下载到 Mac 后用本机证书签名；或直接在本机编译。
- 免费路线验证失败时的备选：付费 Developer ID Application 证书（年费 99 美元）。纯自签名证书没有 Team ID，可能导致 Flutter 动态库验证失败，不作首选。
- 主应用、helper、Frameworks、dylib 都要完整签名，保留必要的 entitlements 和预登录配置。
- 用 A、B 两个连续版本验证：装 A 并授权，覆盖升级到 B，检查权限、锁屏控制、登录窗口和重启上线是否保持。
- 从官方版换成定制版时，等同于新应用，需要重新授权。

### 3.4 功能裁剪与剪贴板

- 被控端在设置中**关闭**不需要的能力，而不仅仅是隐藏入口（评审 #7）：文件传输、音频、终端、TCP 隧道、摄像头、远程修改配置、隐私模式。
- 保留：画面、键鼠、文本剪贴板。
- 剪贴板同步会把敏感文本（密码、密钥）也同步过去，使用时注意；需要时可在会话中临时关闭。
- 第一轮先保持官方功能依赖完成构建，确认能出包后，再逐项裁剪打印驱动、虚拟显示、隐私模式等组件，避免构建问题和裁剪问题混在一起。

### 3.5 Mac 控 Windows 的键盘习惯

RustDesk 已有现成开关：会话工具栏里的 "Swap control-command key"（对应选项 `allow_swap_key`），Mac 控 Windows 时出现 **[已核实]**。不需要自己写按键映射。实测 Cmd+C/V、左右修饰键、中文输入法和快捷键冲突。

## 4. 安全设计

1. **访问控制**：每台被控端使用**不同的**永久强密码，仅永久密码模式；开启 TOTP 双重认证（开源版支持，不需要 Server Pro **[已核实]**）。注意"可信设备"可能免除后续 TOTP，需要知道如何撤销可信设备。
2. **服务器信任根**：客户端内置服务器公钥，服务端 `-k _`。公钥不是接入凭据（见第 2 节）。
3. **加密**：成功完成安全握手的连接为端到端加密，中继只看到密文。客户端存在"非安全连接"回退并会弹窗确认，**出现不安全连接提示时不点继续，停止排错**（评审 #6）。
4. **VPS 被攻陷的影响**：攻击者拿到服务器私钥后可以冒充服务器，因此不能宣称"VPS 被攻陷完全无影响"。私钥加密备份、限制访问；一旦泄露，换密钥并重新出包。
5. **云服务器加固**：防火墙只放行第 3.1 节端口；SSH 仅密钥登录。
6. **最小权限**：见第 3.4 节。
7. **三类密钥分开管理**：服务器身份私钥、终端配置、代码签名私钥（评审 #9）。

## 5. 带宽与云服务器选型

以下为**初始估算**，以强制中继实测为准（评审 #12）：

- 打洞成功时，数据不经过服务器，只有很小的心跳流量。
- 中继时，办公场景 1080p 大约持续 1–3 Mbps，对应单向约 0.45–1.35 GB/小时，另有协议开销。
- 选型：先选峰值带宽 ≥ 5 Mbps 或按流量计费的套餐，实测后再调整。服务器带宽不能弥补终端上行不足或高丢包。
- 机房选离两台电脑都近的地域。

## 8. 测试清单（评审 #10）

**网络**
- 家里 ↔ 公司、手机热点 ↔ 家里：连接成功率、直连还是中继、延迟。
- 人为让直连失败但服务器可达，确认实际经 hbbr 连接并显示安全连接。
- 两端网络切换后能否自动重新注册。

**Windows 无人值守**（每项都要验证画面**和**键鼠输入，"有画面"不算通过）
- 未登录、锁屏、UAC 安全桌面。
- 重启后服务自动启动，身份为 LocalSystem。
- 被控端退出界面程序后仍可被连接。

**Mac 无人值守**（记录 macOS 版本、FileVault 状态、签名身份）
- 已登录锁屏：远程输入密码解锁。
- 注销后登录窗口：远程看到并输入密码登录。
- 重启：FileVault 已关闭、自动登录开启，重启后无人操作应可远程连接并操作。

**安全**
- 错误服务器公钥应连接失败。
- 正确密码 + 错误/缺失 TOTP 应被拒绝（用未受信任的新会话测试）。
- 重启后 TOTP 配置仍生效。
- 出现"不安全连接"提示即判为失败。

## 9. 风险与备选

| 风险 | 影响 | 对策 |
|---|---|---|
| 关闭 FileVault | Mac 丢失时数据可被读取 | 用户已接受；开机自动锁屏、强登录密码 |
| 免费证书签名的应用无法运行或权限不保持 | 定制版在 Mac 上不可用 | 改用付费 Developer ID 证书 |
| 编译链复杂 | 定制版出包受阻 | 阶段 0 的"官方客户端 + 自建服务器"已可日常使用，作为兜底 |
| 改名不完整导致升级/卸载找错服务 | 残留旧服务、升级失败 | 按评审清单逐项处理，安装包验收覆盖升级和卸载 |
| 升级后远程失效 | 远程无法恢复 | 手动升级、保留上一版、先在 Mac 上试再升级 Windows |
| 服务器私钥泄露 | 可被冒充服务器 | 加密备份、限制访问、泄露后换密钥重新出包 |
| 跟进上游的合并成本 | 长期维护负担 | 改动集中、记录版本锚点、定期合并安全更新 |
| AGPL-3.0 | 自用无影响，分发需开源 | 仅自用 |

备选方案（未采用）：

- **Tailscale/ZeroTier + 系统自带远程桌面**（Windows RDP + Mac 屏幕共享）：组网工具只解决网络，还要两套桌面协议，也满足不了改名要求；协调和中继依然依赖第三方。注意 Windows 家庭版不能作为 RDP 被控端。
- **官方客户端 + 自建服务器**（即阶段 0 的状态）：维护最省，但不能改程序名和进程名。如果以后放宽改名要求，可以停在这一步。
- **从头自研**：工作量大，打洞、编码、无人值守都要重写。
